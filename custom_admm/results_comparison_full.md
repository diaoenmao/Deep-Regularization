## 八、结论和建议

### 关键发现

1. **新架构（consistent）表现显著差于原架构**
   - 平均下降 36.98%
   - 所有 4 个数据集均出现下降

2. **Ring 任务受影响最大**
   - 下降 51.85%
   - m=16,32,64,2048 结果为 0（完全失败）

3. **m=1024 是一个例外**
   - 在 4 个数据集中有 3 个新结果优于或等于原结果
   - 可能暗示某种特定维度下的规律

4. **Ring+XOR+Sum 最稳健**
   - 下降幅度最小（-20.83%）
   - m=6,8,16,2048 与原结果接近

### 建议操作

1. **不要使用当前新架构的结果替换原结果**
   - 性能差距过大（-36.98%）

2. **调查架构差异的根本原因**
   - latent_size 从 32 增加到 58 可能导致欠拟合
   - n_hidden_layers 从 2 增加到 5 可能增加优化难度

3. **重新调参**
   - 当前 feat_drop=0.6 是原架构的调优值
   - 新架构可能需要不同的超参数

4. **检查 m=1024 的规律**
   - 为什么在多个数据集上 m=1024 表现更好？
   - 是否存在维度相关的系统性问题？

## 附录 B：模型容量与特征维度的关系分析

### 关键观察：m=1024 的"反常"现象

在 4 个数据集中，有 3 个数据集在 **m=1024** 时新架构表现优于或等于原架构：

| 数据集 | m=1024 原结果 | m=1024 新结果 | 差异 |
|--------|-------------|-------------|------|
| XOR | 33.33% | 66.67% | **+33.33%** |
| Ring | 16.67% | 41.67% | **+25.0%** |
| Ring+XOR | 16.67% | 33.33% | **+16.67%** |
| Ring+XOR+Sum | 38.89% | 47.22% | **+8.33%** |

### 假设 1：模型容量与任务复杂度的匹配

| 架构 | latent_size | n_hidden_layers | 总参数量（约） |
|------|-------------|-----------------|---------------|
| 原架构 | 32 | 2 | ~2K |
| 新架构 | 58 | 5 | ~10K |

**解释**：
- **低维任务 (m < 512)**：任务相对简单，原架构（小模型）足以拟合
  - 新架构（大模型）可能**过拟合**或**优化困难**
  - 尤其在 Ring 任务上，新架构在 m=16,32,64 时 best_k=0%，说明完全失效

- **高维任务 (m = 1024)**：任务复杂度增加
  - 原架构容量不足，开始失效
  - 新架构容量更大，开始展现优势

- **超高维任务 (m = 2048)**：两者都失效
  - 可能都远低于最优容量
  - 或者需要更强的正则化

### 假设 2：优化动力学的维度效应

**可能原因**：
1. **梯度稀疏性**：高维空间中，梯度可能更稀疏，大模型的优化优势更明显
2. **特征冗余**：m=1024 时，特征间冗余度高，大模型更能利用这种冗余
3. **ADMM 收敛性**：高维情况下，ADMM 的收敛性可能依赖于模型容量

### 假设 3：sweet spot 假说

每个架构可能有一个"最优维度范围"：

```
原架构 (32-2-58):  [m=2    ━━━━━━●━━━━━━ m=512]   最优在低维
新架构 (58-5-58):  [m=512  ━━━━━━●━━━━━━ m=2048]  最优在高维
                          ↑
                      m=1024 是新架构的 sweet spot
```

### 验证建议

1. **增加中间维度测试**：在 m=768, 1536 等位置测试，验证 sweet spot 假说
2. **检查训练曲线**：比较原/新架构在不同维度下的收敛速度
3. **分析特征重要性分布**：检查大模型是否学到更合理的特征重要性
4. **尝试中等容量模型**：如 latent_size=45, n_hidden_layers=3-4，寻找最优配置

## 附录 A：标准差 (std) 计算说明

### std 的来源：6 折交叉验证 (6-Fold CV)

**不是**通过不同 seed 计算的！std 来自于**6 折交叉验证的 fold 间差异**。

### 计算流程（以 `run_ablations.py` 为例）

```python
# 第 34-77 行
def eval_synthetic(method, ds_name, k_true, ns, hp_overrides=None):
    """在合成数据集上运行 6 折交叉验证，返回每个维度的结果。"""
    results = []
    for n_features in ns:
        np.random.seed(SEED)  # 固定种子 (SEED=0)
        torch.manual_seed(SEED)
        X, X_tilde, y = generate_dataset(ds_name, N_SAMPLES, n_features)

        # 6 折交叉验证
        splits = list(KFold(n_splits=6).split(X))
        best_ks = []  # 存储 6 个 fold 的 best_k 值

        for train_idx, test_idx in splits:
            # ... 训练和评估 ...
            ranked = np.argsort(np.abs(scores))
            best_ks.append(sum(i in correct for i in ranked[-k:]) / k)

        # 计算平均值和标准差
        bk = np.mean(best_ks) if best_ks else 0
        bk_std = np.std(best_ks) if best_ks else 0  # ← std 来自这里

        results.append({"m": n_features, "best_k": bk, "best_k_std": bk_std})
```

### 示例计算

假设某个数据集在 6 个 fold 上的 best_k 分别为：
```
[1.0, 0.5, 1.0, 0.0, 0.5, 1.0]
```

则：
- **mean** = (1.0 + 0.5 + 1.0 + 0.0 + 0.5 + 1.0) / 6 = **0.6667 (66.67%)**
- **std** = sqrt(sum((x - mean)²) / 6) = **0.3727 (37.27%)**

### 对比表中的 std 值示例

| 数据集 | m | best_k | best_k_std | 可能的 6-fold 分布 |
|--------|---|--------|-----------|------------------|
| XOR | 512 | 66.67% | 47.14% | [1.0, 0.0, 1.0, 1.0, 0.0, 1.0] |
| Ring | 64 | 91.67% | 18.63% | [1.0, 1.0, 0.5, 1.0, 1.0, 1.0] |
| Ring | 128 | 50.00% | 40.82% | [0.0, 0.5, 1.0, 0.0, 0.5, 1.0] |

### 关键点

1. **固定种子**：所有实验使用 `SEED=0`，数据生成是确定性的
2. **变异性来源**：6 折 CV 中不同 fold 的数据划分导致结果差异
3. **std 的意义**：反映模型在不同数据划分上的稳定性
   - std=0：6 个 fold 结果完全一致
   - std 大：不同 fold 结果波动大，模型不稳定
